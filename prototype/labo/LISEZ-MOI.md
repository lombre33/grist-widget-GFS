# Le labo « vrai Grist »

Les mesures du prototype (étape 2 du plan) : GFS et ses apps tournent dans un **vrai Grist** (grist-static 0.1.6, dans Chromium), jamais contre un
faux Grist écrit par nous. Chaque essai se joue à la vraie souris et au vrai clavier (Playwright), à 700 × 400 quand il s'agit d'une interface.

## Lancer un essai

Il faut `node` (22), `npm` et Chromium avec Playwright (le conteneur du cloud les a).

```bash
cd prototype/labo
npm install                                                       # grist-static
bash build-mirror.sh                                              # Publipostage+ seulement : le miroir de ses bibliothèques de CDN
REPO_DIR="$(realpath ../..)" node lab-server.mjs &                # Grist sur 8910, GFS et les apps sur 8911
REPO_DIR="$(realpath ../..)" node run-ordre.mjs                   # un essai ; la sortie dit « OK » ou « ÉCHEC »
```

Le miroir ne construit que les bibliothèques de l'app. Celles que GFS porte (Plotly et ECharts, pour le graphique) n'y sont pas : à leur adresse de CDN, le labo
rend la copie de GFS (`vendor/…`, nommée par `bibliotheques/catalogue.json`), qui a les mêmes octets et la même empreinte que le CDN.

L'attribut `integrity` des scripts est neutralisé (le miroir ne rend pas toujours les octets exacts du CDN), sauf dans les sondes et pour un script que GFS sert
lui-même (`vendor/…`) : là, le navigateur contrôle l'empreinte pour de bon, y compris pour un module dans un sous-cadre à origine opaque.

Variables utiles : `LAB_LANG=fr|en`, `LAB_SCHEME=light|dark`, `LAB_BROWSER=chromium|firefox|webkit` (les deux derniers : sur une machine qui les a),
`LAB_CONSOLE=error|all` (la console du navigateur), `LAB_BYPASS_CSP=1` (diagnostic seulement, jamais une mesure), `LAB_API_EVAL=1` (le script de l'API des widgets servi dans un `eval(…)` : voir juste en dessous).

**Le script de l'API des widgets que le labo sert n'est pas celui de `docs.getgrist.com`.** Le cloud n'atteint pas cet hôte : le labo sert à sa place le fichier de grist-static (`dist/grist-plugin-api.js`) et, dans un vrai serveur, celui du Docker (`labo/lab-serveur.mjs`). Ni l'un ni l'autre
n'évalue de texte ; le fichier de `docs.getgrist.com` le fait (`eval()`, console du porteur le 04/11 ; faits vérifiés 27), et une page dont la politique de sécurité n'a pas `'unsafe-eval'` n'y démarre pas. Form+ est restée muette chez le porteur sans que le labo le voie, jusqu'à la consigne 018.
**`LAB_API_EVAL=1`** sert le fichier du labo enveloppé dans un `eval(…)` (`api-evaluee.mjs`, gardé par `test/api-evaluee.test.mjs`) : toute passe qui ouvre une app se rejoue ainsi (`LAB_API_EVAL=1 REPO_DIR="$(realpath ../..)" node run-ouvrir-form.mjs`), et une app qui refuse l'évaluation y échoue comme chez
le porteur (`EvalError`, puis `grist` vide, l'app reste sur « Connexion à Grist… »). Ce n'est **pas le défaut** : tant qu'une app de la suite n'a pas `'unsafe-eval'` pour ce fichier (guide des apps, règle 11), ses passes échoueraient sans que GFS y puisse rien ; il le deviendra quand Form+ aura appliqué la 018.

**Le cadre que Grist donne à GFS n'est pas tout à fait celui d'un Grist ordinaire.** grist-static lui ajoute l'attribut `credentialless` (`ext/app/client/HookStub.ts` : `iframeAttributes`) ;
un Grist ordinaire n'ajoute rien (`DefaultHooks.ts`). Sous Chromium, un cadre anonyme coupe `window.opener` et le nom de toute fenêtre ouverte depuis lui, et `window.open` y rend `null` : le labo
dirait « l'ouvreur est coupé » là où le Grist de la personne le garde. Firefox ne connaît pas l'attribut. Pour une mesure qui dépend d'une fenêtre ouverte par une app :
`startLab({ ordinaryFrame: true })` (`lab-setup.mjs`), ou `CAP_ORDINAIRE=1` pour `run-capacites`. Le défaut reste le cadre de grist-static, pour ne pas changer les passes déjà mesurées ; le détail est dans `docs/faits-verifies.md`, section 1.

## Un vrai serveur Grist, pour ce que grist-static n'a pas

grist-static n'a ni API REST ni jeton, et le répondeur de `run-reel` est un faux écrit par nous : il avait caché la garde de Grist contre les formulaires d'un autre site (le 03/11, la sonde
échouait chez le porteur, pas dans le labo ; `docs/faits-verifies.md`, section 14). Toute mesure qui dépend du serveur (REST, jetons, CORS, pièces jointes, taille d'un envoi) se joue donc
d'abord sur un **vrai serveur** :

```bash
cd prototype/labo
bash vrai-serveur.sh                                     # Docker : l'image officielle gristlabs/grist (1.7.19 par défaut, la version du porteur), sur 127.0.0.1:8484
REPO_DIR="$(realpath ../..)" node run-reel-serveur.mjs   # la sonde reel/ ajoutée à un document créé pour l'essai, jouée à la vraie souris ; « OK » ou « ÉCHEC »
REPO_DIR="$(realpath ../..)" node run-pdf.mjs            # GFS lui-même dans un document neuf : les PDF qu'il garde (contrats 6.6)
REPO_DIR="$(realpath ../..)" node run-lire.mjs           # lire un PDF que GFS garde, dans une app d'essai (contrats 5.4, point 8)
REPO_DIR="$(realpath ../..)" node run-ranger-pdf.mjs      # une app d'essai range ses exports PDF dans GFS (contrats 5.4, point 9) ; LAB_KIT=1 : avec le client du kit
REPO_DIR="$(realpath ../..)" node run-corbeille.mjs        # la corbeille des PDF de GFS : mettre, restaurer, supprimer pour de bon, vider, au clavier (décision du 04/11)
REPO_DIR="$(realpath ../..)" node run-corbeille-apps.mjs        # la corbeille des fichiers des apps (Publipostage+) : mettre, restaurer au même numéro, la vraie app ouvre le modèle restauré (décision du 04/11)
REPO_DIR="$(realpath ../..)" node run-copie.mjs        # la copie depuis l'explorateur : Dupliquer, Ctrl+C / Ctrl+X / Ctrl+V, un PDF sans octet de plus, la vraie app ouvre la copie (décision du 04/11)
```

`lab-serveur.mjs` (le serveur, la session de la personne d'essai, un document neuf, un widget ajouté à la vraie souris) et `lab-pdf.mjs` (GFS à 700 × 400, ce que le serveur retient lu par l'API REST,
les gestes de l'explorateur, le contraste de chaque texte) sont communs aux essais du vrai serveur : un nouvel essai s'écrit en quelques lignes de scénario.

Dans le conteneur du cloud, le script lance lui-même le démon Docker (sans réseau de pont) ; l'image se tire seule, la première fois. Le serveur n'a qu'une personne d'essai
(`essai@example.com`), ses documents sont dans `/tmp/grist-persist`. `GRIST_VERSION`, `GRIST_PORT` (script) et `GRIST_URL` (essai) changent la version, le port et l'adresse. Chromium seul :
la mise en page sous Firefox se mesure à part (« L'interface sous Firefox », ci-dessous) ; ce que le Firefox du porteur dit des cadres, des fichiers et de ses extensions, seul le porteur le mesure (la sonde publiée, plus bas).

- **Firefox absent : l'essai est sauté, et le dit** (le résumé de `node --test` compte une suite sautée). Sur une autre machine, il trouve Firefox à ses emplacements usuels ; `GFS_FIREFOX=<fichier exécutable>` désigne un autre Firefox,
  `GFS_FIREFOX_DIR` le dossier où `installer-firefox.sh` le pose (défaut `~/.cache/gfs-firefox`).
- **Aucune bibliothèque** : `test/firefox.mjs` lance Firefox et le pilote par WebDriver BiDi, le protocole qu'il parle de lui-même (`--remote-debugging-port`), avec le WebSocket de Node 22. Ni geckodriver, ni Selenium, ni Playwright
  (qui ne pilote qu'un Firefox modifié par lui, dont les hôtes de téléchargement sont refusés dans le cloud). La largeur et le zoom (`devicePixelRatio`) se règlent par page (`page.view`), la souris et le clavier sont ceux du navigateur
  (`input.performActions`, jamais `dispatchEvent`). Un seul Firefox sert tout le fichier.
- **Pour mesurer autre chose** : écrire une fonction qui s'exécute dans la page (`page.run(fn, …args)`, son résultat revient en JSON) et agir avec `page.click(x, y)` et `page.press('Escape')` ; la page d'essai se complète dans
  `test/pages/explorateur.js`. Chaque écart est un `{ kind, text }` : le rapport les groupe par nature. Les mesures de la liste et des vignettes (`labo/mesures-liste.mjs`) sont écrites une fois, pour cet essai et pour `run-liste`
  (Chromium, dans un vrai Grist) : une nouvelle mesure de la liste s'y ajoute, pas dans l'un des deux.
- **Le calendrier du kit** (`test/mesures-calendrier.mjs`, joué par le même fichier) : la page d'essai du kit (`prototype/kit/navigateur/calendrier.html`) à 700 × 400, en français et en anglais, en clair et en sombre : le mois (titre, 42 jours, six semaines, barre d'outils sur une ligne, « +2 »), le clic, la liste d'un jour, la saisie rapide, la semaine (blocs à leur place, ouverture vers 7 h) et le glisser-déposer **jusqu'où ce Firefox le mène** : `Page.drag` lance `dragstart`, `dragenter` et `dragover`, jamais `drop` ni `dragend` (aucun Firefox sans écran n'achève un glissement HTML5, même sur une page de deux éléments, avec ou sans Xvfb), donc l'essai vérifie le départ (effet « move », un texte) et l'accueil de la cible (`dragover` annulé, effet « move »). Le dépôt et le retour d'un événement refusé se jouent sous Chromium (`run-calendrier-kit`). Sans `prototype/kit/js/calendrier/`, cette partie est sautée.
- **Entrée et Espace sur un bouton ne se jouent pas ici** : dans ce Firefox sans écran, `document.hasFocus()` reste faux et les touches arrivent (keydown, keypress, keyup sur le bon bouton) sans qu'aucun clic ne parte, même pour un
  `<button>` seul dans une page vide (mesuré le 03/11, Firefox 159, avec et sans `browsingContext.activate`) ; la souris clique, et Tab et Échap (écoutés par le script de la page) marchent. Ces deux touches restent à la mesure
  du labo, sous Chromium (`run-ranger-pdf` : Tab va à la case, Espace la coche, Entrée choisit « Remplacer »).
- **Ce que cet essai ne dit pas** : tout ce qui dépend de ce que Grist envoie (accès, messages, réglages, cadre reconstruit) reste au labo (vrai Grist, Chromium) ; ce que Firefox fait des cadres isolés, des téléchargements et des
  extensions (LanguageTool) reste à la sonde du porteur (ci-dessous).

## Ce que seul ton navigateur ou ton Grist peut dire

Deux pages se publient avec le reste du dépôt (GitHub Pages) et se lancent d'un clic, sans rien installer. Elles ne servent qu'aux mesures.

1. **Ton navigateur** (Firefox, Safari, ou celui d'un client) : ouvre
   `https://lombre33.github.io/grist-widget-GFS/prototype/labo/navigateur/index.html`, laisse la page mesurer l'ordre des écouteurs, clique sur les boutons du
   cadre de haut en bas, réponds aux questions (un fichier arrivé ? une fenêtre ouverte ?), puis « Copier le résultat ». Aucun document Grist n'est touché.
2. **Ton vrai Grist** : dans un document de **test**, ajoute un widget personnalisé à l'adresse
   `https://lombre33.github.io/grist-widget-GFS/prototype/labo/reel/index.html`, accorde-lui l'accès complet (panneau de droite), note la version de Grist
   (menu Aide, « À propos de Grist »), lance la **lecture** (elle ne modifie rien), puis, si tu le veux, l'**écriture** (une confirmation te sera demandée : elle
   crée une table d'essai, joue dessus une vingtaine d'actions de Grist et la supprime), les **pièces jointes** (une confirmation aussi : elle envoie deux petits
   PDF d'essai avec un jeton qui écrit (et, pour comparer, un envoi sans l'en-tête `X-Requested-With`, que Grist doit refuser), les range dans la cellule d'une table d'essai, les relit, les télécharge, puis supprime la table ; les deux fichiers restent
   7 jours dans le document avant que Grist les efface) et la **taille maximale** (une confirmation aussi : des fichiers d'essai de 0,1 à 50 Mo, jusqu'au premier
   refus, 77 Mo au plus), puis « Copier le résultat ». Le texte ne contient ni le jeton ni l'identifiant du document.

GitHub Pages met tout en cache dix minutes : après une mise à jour, recharge la page avec Ctrl+F5 (⌘⇧R sur Mac).

Pour refaire à la main, sur une machine qui a Firefox et WebKit de Playwright, ce que le cloud ne peut pas faire :
`npm install && npm install --no-save playwright && npx playwright install chromium firefox webkit`, lancer `lab-server.mjs`, puis
`LAB_BROWSER=firefox REPO_DIR=… node run-ordre.mjs`, de même pour `run-routeur.mjs`, `run-navigateur.mjs` et `run-politique.mjs`.
