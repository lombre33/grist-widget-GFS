# 030 · Tout en anglais : les colonnes de ta table de configuration passent par la fenêtre commune de mise à jour des noms (kit 0.29.1), sans casser les documents déjà en service

quand : à ton prochain lot ; du code dans ton app (la fenêtre, la lecture des deux jeux) ; deux réponses à donner dans « Demandes à GFS » ; ton app est déjà chez beaucoup de gens : la lecture des deux jeux sort avant ou avec le renommage

## Quoi

**1. La décision du porteur (25/11).** Tout passe en anglais partout (code, tables, colonnes) ; l'interface reste française et anglaise ; **aucun document ni arborescence perdu**, **pas de table de plus** (un renommage se fait sur place, jamais par copie) ; **GFS lit toujours les deux jeux de noms, sans date de fin** ; la personne le sait avant, par une fenêtre qui ne se passe pas, et **seulement si elle peut le faire** ; les gens sont toujours sur le lien de la dernière version. Ton app est **déjà chez beaucoup de gens** : c'est le cas qui demande le plus de soin.

**2. Livré côté GFS (25/11).** Le kit 0.29.1 (`d061fbf`) a la **fenêtre commune** de mise à jour des noms : `NamesUpdate.run({ port, plan, appName })` et `css/names-update.css` (README du kit, « La mise à jour des noms »). Elle est **bloquante** (ni « Annuler », ni Échap, ni clic sur le voile avant le résultat), dit « quelques secondes » et « vos données ne changent pas, seuls des noms changent », liste les noms sous un titre qu'on ouvre, **ne s'ouvre que pour le propriétaire du document** (les autres continuent sur les noms d'avant, sans fenêtre), envoie **un seul lot** (tout ou rien) et vérifie avant et après : les noms relus, et les lignes comptées si l'app lui donne `rowCount`. Dans GFS, ta fiche déclare la capacité `renommage` (contrats 3.3, point 10) : le courtier laisse passer ton lot, **seulement tes tables et tes colonnes**, le libellé seul. **Sync+ n'est jamais cassé** : une table qui porte la colonne `id_sync` ne change ni de nom ni de colonnes (renommée, elle rend le lien muet sans erreur ; faits vérifiés 160) ; le kit la sort du lot et le dit dans la fenêtre, `outcome.held` te dit lesquelles : ne refais pas cette détection chez toi.

**3. Ce que GFS a déjà déclaré pour toi** (`noms` de ta fiche, **des propositions** de GFS, à confirmer ou corriger) : table `BI_Dashboard_Config` ; colonnes `Nom` → `Name`, `TypeRapport` → `ReportType`, `DateModif` → `ModifiedAt`, `ModifiePar` → `ModifiedBy` (`TableId` et `Config` sont déjà anglais ; `BI_Dashboard_Comments` aussi : `Comment`, `Author`, `CreatedAt`). GFS lit déjà les deux jeux de ces noms (faits vérifiés 158). **Dis ce qui manque** : les colonnes de `BI_Dashboard_UserProbe` si l'une est en français, et toute table ou colonne que ton code lit ou écrit par son nom et que cette liste ne dit pas.

**4. Ce que tu fais** (du code dans ton app, dans l'ordre) :
- **a.** Avance ta référence du kit à `d061fbf` (0.29.1) ou après (commit à part, relu) ; charge `css/names-update.css` après `tokens.css`.
- **b.** Au démarrage, avant de lire tes tables par leurs noms anglais, appelle `NamesUpdate.run({ port, plan, appName: 'Grist-BI' })`. `plan(schema)` rend ton lot (`RenameTable`, `RenameColumn`, et `ModifyColumn` du libellé seul) d'après les noms que le document a **maintenant** : le kit le recalcule sur un schéma relu juste avant d'envoyer (un autre onglet a pu passer avant). Le `port` : `readSchema`, `apply` (un seul `applyUserActions`), `isOwner` = `contexte.role.proprietaire` dans GFS (contrats 5.2, point 8), la preuve du moteur de partage (`createRestPort(…).isOwner`, `GET /webhooks`) quand l'app est seule.
- **c.** **Plus aucun renommage sans la fenêtre**, dans GFS comme seule. Tu lis les deux jeux de noms **dans la version même qui renomme** et sans date de fin ; tu ne crées jamais la table anglaise quand la française existe ; tu ne renommes pas un document qui porte déjà les deux jeux (« Réunir », avec confirmation).
- **d.** Selon `outcome.state` : `none`, `done`, `already` → tu continues ; `wait`, `blocked`, `skipped` → tu continues **sur les noms que le document a** (tu les lis déjà) et tu n'écris rien qui les remplacerait ; `outcome.held` → ces tables se lisent par leurs anciens noms.
- **e.** **Ne donne `rowCount` qu'aux tables que tu sais petites** (`BI_Dashboard_Config`, une ligne par rapport) : pas à `BI_Dashboard_Comments`, qui grossit avec l'usage (compter, c'est lire la table entière, faits vérifiés 161). Sans lui, la fenêtre dit « Terminé » sans le nombre de lignes, et les noms relus prouvent le lot.
- **f.** Une écriture qui répond « table introuvable » ou « colonne introuvable » juste après un renommage venu d'un autre onglet ou d'une autre personne : relis les noms et recommence **une fois** ; sinon dis « Rechargez la page » sans rien écrire de plus (guide des apps 1.1, point 15).
- **g.** Annonce tes noms dans « Changements qui touchent GFS » de `GFS-ETAT.md` **avant** de publier (contrats 2.4, point 6 : GFS les déclare dans `noms`). Plusieurs sections de ton app peuvent partager la même table dans un document, dans des onglets différents : le kit le gère (`already` quand un autre onglet est passé avant) ; ce qui reste à toi est la règle f, pour une section restée ouverte sur l'ancienne page.

**5. Deux questions** (tes réponses vont dans « Demandes à GFS » de `GFS-ETAT.md`) :
- **a.** Quelle version est servie aux gens (le live), et que fait-elle devant un document dont `Nom` est devenu `Name` : lit-elle `Name`, recrée-t-elle `Nom` à côté (ce qui cacherait les rapports sans rien perdre), échoue-t-elle, dit-elle quelque chose ? Une personne qui garde l'ancienne page ouverte pendant la mise à jour de l'autre est le cas à décrire.
- **b.** Quelque chose écrit-il dans tes tables hors de ton app ouverte (un webhook, une automatisation, un export programmé), et par quel nom ?

## Pourquoi

Le porteur veut qu'aucun renommage ne se fasse sans que la personne le sache, qu'aucune ligne ne se perde, et qu'une personne sans les droits ne soit jamais bloquée : elle continue sur les noms d'avant, et les deux jeux se lisent. Une table de Sync+ renommée rend le lien muet sans une erreur (faits vérifiés 160) : c'est pourquoi la fenêtre la garde.
