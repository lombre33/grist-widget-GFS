# 053 · Le geste « joindre » est livré dans GFS : appelle-le pour joindre ton PDF à sa ligne, sans jeton d'écriture (du code dans ton app)

App : Publipostage+ · posée le 06/11/2026 · quand : au prochain lot de ta page ; du code dans ton app (`js/gfs-link.js`, `js/row-attachment.js`, `js/pdf-delivery.js`) ; contrats 2.7 (point 7), 5.4 (point 12), 5.1 (point 4), 5.3 ; suite de ta demande « Suite, PDF joint à la ligne (06/11) », de la 052 et du choix du porteur du 06/11 (« GFS joint lui-même ») ; vaut dans GFS seulement

## Quoi

La 052 disait que ce geste n'existait pas encore : **il existe**, écrit dans les contrats (5.4, point 12) et **mesuré dans un vrai Grist** (voir plus bas). Ton app ne reçoit toujours aucun jeton d'écriture : tu donnes les octets, GFS les envoie à Grist et écrit la cellule.

**1. L'appel `joindre`** (app → GFS, sans délai, 5.1) : `joindre { table, colonne, mode?, fichiers: [{ ligne, fichier, nom }] }`.
- `table` et `colonne` : les identifiants de Grist (la table de ta section, la colonne que la personne a choisie : ton `pp_attach_column`) ; `mode` : `remplacer` (par défaut : un fichier de même nom déjà cité par la cellule en sort, le nouveau prend sa place) ou `ajouter` (ton `pp_attach_mode` : `replace` → `remplacer`, `add` → `ajouter`) ;
- `ligne` : le numéro de la ligne (un entier d'au moins 1) ; `fichier` : un `File` ou un `Blob` fabriqué dans ton cadre (les octets, jamais un jeton) ; `nom` : le nom que Grist garde (1 à 200 signes, « .pdf » ajouté s'il manque). Plusieurs entrées d'une même ligne vont dans la même cellule, dans l'ordre reçu (ton « un document par valeur ») ;
- **au plus 200 entrées par appel** : si tu en as plus, coupe en plusieurs appels, que GFS prend l'un après l'autre. C'est aussi ta façon d'avoir une progression : GFS ne rend son rapport qu'à la fin de chaque appel.

**2. La réponse** : `{ colonne, probleme, joints, echecs }` ; ce que Grist ou le réseau refuse n'est **pas** une erreur de l'appel, le rapport le dit :
- `probleme` vaut `null`, ou ce qui a arrêté le lot : `absente` (la colonne n'existe plus), `inutilisable` (elle n'est plus de type Pièces jointes, ou elle est à formule), `refus` (Grist refuse : droits, règles d'accès), `trop-gros`, `injoignable`, `echec` (autre). Un mot que ce texte ne connaît pas (un GFS plus récent) est à traiter comme `echec` ;
- `joints` : `[{ index, remplace }]`, une entrée par fichier joint (`index` : sa place dans `fichiers`, `remplace` vrai quand il a pris la place d'un fichier de même nom) ; `echecs` : `[{ index, raison }]`, `raison` valant `ligne` (la ligne a été supprimée pendant l'export) ou l'un des mots de `probleme`. Ces mots correspondent un à un aux cas que ton rapport de `attachAll` dit déjà (colonne disparue ou plus de type Pièces jointes, Grist refuse, fichier trop gros, Grist ne répond pas, ligne supprimée) ;
- ce que GFS fait pour de bon : il envoie chaque fichier un à un, **relit la colonne juste avant d'écrire** (une pièce jointe que la personne vient d'ajouter dans Grist n'est pas perdue) puis écrit **un seul lot**. Un envoi que Grist refuse arrête le lot : les fichiers pas encore envoyés sont des échecs du même mot, et rien n'est écrit si aucun fichier n'est parti. En mode `remplacer`, l'ancienne pièce jointe **reste dans la liste des pièces jointes du document** (la cellule ne la cite plus) ; c'est ce que Grist fait.

**3. Les refus de l'appel lui-même** (la promesse est rejetée, avec le `code` et la phrase de GFS, que tu écris dans ton coin d'état) : `GFS_REFUSE` (forme hors règle, type que ton manifeste ne déclare pas dans `actions.joindre`, table que ton manifeste ne laisse pas lire et écrire, contenu qui n'est pas un PDF), `GFS_LECTURE_SEULE` (document en lecture seule), `GFS_INACTIF` (ton app n'est plus l'app active), `GFS_INCONNU` (un GFS plus ancien que ce geste : tu le dis et tu gardes ton PDF téléchargé).

**4. Ce que GFS déclare, et quand** : `actions.joindre: ["pdf"]` dans le manifeste que GFS garde de ton app, **quand ta page dit « 053 · faite »**, comme pour `actions.ranger` (043). D'ici là l'appel reçoit `GFS_REFUSE` : ta case « Joindre à la ligne » n'a toujours pas d'effet dans GFS, comme la 052 le disait.

**5. Où le brancher** : `RowAttachment.attachAll` (`js/row-attachment.js:163`) reste le seul point de branchement. **Hébergée** (`GfsLink.hosted`), elle ne demande plus `getWriteAccess` ni ne fait `upload` et `linkAll` : elle appelle `joindre` avec les octets de chaque PDF et la ligne d'où il vient, puis traduit le rapport dans ton rapport actuel. **Seule**, tout reste comme avant (le jeton de Grist, l'API REST). Le client du kit (`grist-factory-kit` 0.11.0, `js/gfs-link.js` : `attach`, `normalizeAttach`, ses essais dans `test/gfs-link.test.mjs`) est écrit sur le modèle de ton `deposit` : reprends sa fonction dans ton `js/gfs-link.js` (même forme, mêmes refus, aucune dépendance), sans copier ses commentaires.

**6. Garder la colonne et le mode d'une ouverture à l'autre** : GFS ne déclare toujours ni `pp_attach_column` ni `pp_attach_mode` dans `reglages` (052). Le stockage de la personne (5.3) le permet sans rien déclarer : `stockage.ecrire` avec une clé de 1 à 64 signes (`A-Z a-z 0-9 _ . : -`) ; il vaut pour tout le navigateur, tous les documents de l'instance mêlés, donc mets le document dans la clé si ton choix est propre à un document. C'est ta décision, GFS n'ajoute rien.

**Mesuré** (vrai Grist 1.7.19, Chromium, français clair et anglais sombre, `labo/run-joindre.mjs`, 35 vérifications, avec et sans le client du kit ; faits vérifiés 48 et 49) : les octets que Grist garde sont ceux de ta sonde (même empreinte) ; `remplacer` et `ajouter` ; plusieurs fichiers sur plusieurs lignes dans un appel, l'ordre gardé ; une ligne supprimée ; une colonne absente, d'un autre type ou à formule ; une table de GFS, une table interne, un contenu qui n'est pas un PDF ; un refus de taille (413) et un réseau qui tombe ; une pièce jointe ajoutée dans Grist pendant l'envoi ; une règle d'accès qui refuse d'écrire la colonne (Grist répond « Blocked by column update access rules », ton rapport porte `refus`). **Pas mesuré** : Firefox (le geste n'a pas d'interface), l'instance de la DINUM, ta vraie app qui appelle `joindre` (GFS la rejoue quand tu auras dit « faite »).

## Pourquoi

Le porteur a choisi le 06/11 que GFS joigne lui-même le fichier : GFS est le seul à parler à Grist, et aucune app ne reçoit une écriture large sur des documents qu'elle ne lit pas. Tu avais dit ce que ton code a en main au moment de joindre (`attachAll(tableId, items, progress)`, le rapport par PDF) : l'appel est fait pour cela.
